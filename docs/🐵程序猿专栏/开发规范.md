## css（vue项目）

### 引入规范

- 方案一：`<style scoped> + :deep()`
- 方案二：`严禁使用 scoped。采用 BEM + CSS Variables 方案`

::: tip 小贴士
为何 Element Plus 官方未采取方案一？
因为 Element Plus 是“被引用的库”，而不是“最终的 App”。两者的立场截然相反：

立场 1：必须将“样式覆盖权”完全交给用户
如果 Element 内部使用了 scoped，那么用户想要修改一个按钮的颜色，就需要面对 Vue 生成的随机 data-v-hash 属性。由于用户代码在 Element 组件之外，没有相同的 data-v 属性，scoped 天然阻止了外部样式侵入。
即使 Element 用 :deep() 主动穿透，也无法预料用户会将组件嵌套在何种 DOM 层级下。唯一稳妥的方案是：组件自身不用 scoped，让所有样式基于纯粹的 Class（BEM 命名），用户只需写 .el-button 即可轻松覆盖。

立场 2：CSS 变量（Design Tokens）才是主题化的未来
Element Plus 的样式核心依赖是 CSS Variables（var(--el-color-primary)）。结合 BEM，它们实现了运行时的主题切换（无需重新编译）。
如果用了 scoped，CSS 变量会被锁定在组件实例中，无法实现全局一键换肤的高效特性。此外，scoped 会让样式难以抽取为独立的静态 index.css 文件供 CDN 加载。

立场 3：避免 SSR（服务端渲染）与 Hydration 的水合风险
scoped 生成的 data-v-* 属性依赖于客户端 JS 执行。在 SSR 流式渲染中，如果样式表先加载，DOM 后注水，短暂的属性不匹配可能导致样式闪烁（FOUC）。纯 Class 方案在服务端字符串拼接时就能完整确定样式，更为稳健。
:::

::: warning 使用建议
在内部业务系统中使用方案一：

可以在 index.scss 中引入公共样式，然后每个组件使用组件内的 scope 样式。

在开发组件库时使用方案二，且需要注意：

在 index.scss 中引入所有样式文件，并在入口文件 main.ts 中引入 index.scss
可以在 index.scss 中引入公共样式，然后每个组件对应一个同名的.scss文件并同样在 index.scss 中引入
:::

::: error
最好不要在 index.scss 中引入变量定义和混入，它们属于css工具最终不产生实际的 css 代码。
因此建议完全区分开，变量定义和混入使用：css.preprocessorOptions.scss.additionalData 进行配置。
:::

::: tips
在 style 标签内引入为：

@use '@styles/navigation.scss';

在 script 标签内引入样式为：

import '@styles/navigation.scss'
:::
