# 事件循环

## 为什么需要事件循环？
JavaScript 是**单线程**语言，同一时间只能做一件事。  
为了避免长时间等待（如网络请求、定时器、用户交互）造成页面卡顿，浏览器提供了 **Web APIs** 和 **事件循环** 机制，让 JS 能够以非阻塞的方式处理异步操作。

---

## 核心概念

| 概念 | 说明 |
|------|------|
| **调用栈（Call Stack）** | 后进先出的执行栈，记录当前正在执行的函数。 |
| **Web APIs** | 浏览器提供的异步接口（如 `setTimeout`、`DOM` 事件、`fetch` 等），不在 JS 引擎内。 |
| **任务队列（Task Queue）** | 存放等待执行的**宏任务**回调。 |
| **微任务队列（Microtask Queue）** | 存放等待执行的**微任务**回调，优先级高于宏任务。 |
| **事件循环（Event Loop）** | 不断检查调用栈是否为空，如果为空则从微任务/宏任务队列中取出任务执行。 |

---

## 调用栈（Call Stack）

后进先出，函数调用会入栈，执行完毕出栈。

```js
function foo() {
  console.log('foo');
}
function bar() {
  foo();
  console.log('bar');
}
bar();
// 输出：foo → bar
```

调用栈变化：

```text
bar() 入栈 → foo() 入栈 → 执行 foo() 出栈 → 执行 bar() 出栈
```

## 微任务（MicroTask）

常见微任务来源：

- Promise.then / Promise.catch / Promise.finally
- async/await（await 后面的代码会放入微任务）
- MutationObserver
- queueMicrotask()
- process.nextTick（Node.js，优先级高于其他微任务）

执行规则：
每次执行完一个宏任务后，会清空当前微任务队列中所有微任务，然后再取下一个宏任务。

## 宏任务（MacroTask）

常见宏任务来源：

- setTimeout / setInterval
- I/O 操作（如 fetch 回调）
- UI 渲染（requestAnimationFrame 是单独的渲染队列，但在事件循环中也涉及）
- setImmediate（Node.js）
- MessageChannel

## 事件循环完整流程

1. 执行同步任务（全局代码），调用栈清空。
2. 遇到异步操作时，回调被交给 Web API，处理完成后：
   - 微任务回调进入微任务队列
   - 宏任务回调进入宏任务队列
3. 当前任务执行完毕，调用栈清空。
4. 清空微任务队列（按顺序执行此时此刻回调的所有微任务）。
5. 从宏任务队列中取出下一个宏任务执行。 
6. 重复步骤 4-5。

## 代码执行顺序示例

### 嵌套微任务

```js
Promise.resolve().then(() => {
  console.log('1');
  Promise.resolve().then(() => {
    console.log('2');
  });
});

setTimeout(() => {
  console.log('3');
}, 0);

console.log('4');
```

```text
4
1
2
3
```

**解释：**

同步任务：`4`

清空微任务队列：输出 `1` 时又产生了新的微任务 `2`，因此微任务队列清空后才会执行宏任务 `3`。

### async/await

```js
async function foo() {
  console.log('a');
  await bar();
  console.log('c');
}
async function bar() {
  console.log('b');
}
console.log('1');
foo();
console.log('2');
```

**输出：**

```text
1
a
b
2
c
```

**解释：**

`await bar()` 相当于：`Promise.resolve(bar()).then(() => { console.log('c'); });`
